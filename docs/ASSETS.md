# Asset provenance

Every visual asset on this site is either drawn in code in this repository or
generated by a script in this repository. Nothing is downloaded from an asset
library, nothing is traced from a photograph, and nothing carries a third-party
licence except the two typeface families, which are OFL and shipped with their
licences.

## The computer on the home page

`src/assets/scene/crt.webp` and `crt@half.webp`.

**Modelled and rendered from scratch** by `tools/model_crt.py`, which builds the
machine procedurally in Blender and renders it with Cycles. There is no purchased
model, no scanned mesh, no stock render, and no photograph involved. The script is
the source: delete the images and re-run it and you get them back.

```bash
"/c/Program Files/Blender Foundation/Blender 5.1/blender.exe" -b --factory-startup \
  --python tools/model_crt.py -- --out "$(pwd)/src/assets/scene" \
  --samples 300 --width 2600 --height 2340
```

| | |
|---|---|
| Renderer | Blender 5.1.1, Cycles, OptiX on an RTX 3060 |
| Samples | 300, adaptive, with denoising |
| Render time | about 2 minutes |
| Colour management | Standard view transform (AgX desaturated the beige to grey) |
| Master | `crt.png`, 2600 x 1642, RGBA — **not committed**, it is a build artefact |
| Shipped | `crt.webp` 213 KB, `crt@half.webp` 74 KB, both RGBA WebP quality 90 |
| Served | via `srcset`, so a phone fetches the 1300px file |

**What is modelled:** a 17-inch CRT at real size — 400mm across the front, 390mm
tall, 420mm deep. A front moulding carrying the bezel, a rear shell that tapers
toward the tube neck, a 4mm seam between the two mouldings, ventilation slots cut
through both sides and the top, a bevel on every edge, a recessed tube, a power
rocker with a moulded ring, four adjustment buttons, a lit power indicator, a blank
maker-plate recess, a tilt stand on a base, and a keyboard whose keycaps are
generated across a plane in perspective with real 19mm pitch and a dished top.

**Materials:** beige moulding with a slow tonal drift across each panel, fine
moulding grain as a bump, and roughness that varies with a noise texture — so a
large flat panel does not read as one flat fill. The wear is deliberately slight.

**Lighting:** a warm near-neutral key, a cyan area light from the right and a violet
rim from behind and above, plus a dim fill. The key is warm on purpose: under a cyan
key the beige turned grey-green and stopped reading as period plastic. The cyan and
violet describe the edges rather than colouring the faces.

**The screen is deliberately blank in the render.** The typed introduction is live
DOM text laid over the glass, not baked into the image.

## How the live text is aligned

The camera is **level and framed by lens shift**, never rotated. A plane parallel to
the image plane projects to a similar rectangle wherever it sits in frame, so the
screen renders as a true axis-aligned rectangle at exactly 4:3, and the HTML overlay
needs no perspective transform. Depth still reads because the machine sits well off
the optical axis, which is what reveals its right side and the top of the keyboard.

The renderer measures where the tube lands in the finished image and writes it to
`src/assets/scene/crt.json`. `build.mjs` turns that into the CSS custom properties
the overlay uses, so the numbers are never copied by hand:

- `--screen-left/top/width/height` — the tube's rectangle within the asset
- `--screen-clip-*` — how much of the tube the front moulding hides, applied as a
  `clip-path` so the text is occluded by the bezel instead of painted over it
- `--screen-cx/cy` and `--crt-aspect` — the glass centre as fractions, which the
  narrow-screen rules use to solve "put the screen here" arithmetically

`build.mjs` refuses to build if the renderer ever reports a skewed screen, which is
what would happen if someone tilted the camera. Measured skew is currently 0.000%.

## Fonts

See `src/assets/fonts/README.md`. Fraunces, Karla and VT323, all SIL Open Font
License 1.1, all self-hosted with their licence files.

## Everything else

The room, the desktop wallpaper, the window chrome, the taskbar and the favicon are
CSS and inline SVG written in this repository. The Windows-era desktop is an
original reconstruction of the period's *construction* — gradient title bar, compact
window controls, bevelled and inset surfaces, a green Start tab — in this site's own
colours. It contains no Microsoft logo, no Luna artwork, and no borrowed icon set;
the Start mark and the window icon are the lit doorway used elsewhere on the site.
